# 合批方法

## 分母与范围

项目根的[CAVALRY_2_8_MIGRATION_PLAN.md](../../../../CAVALRY_2_8_MIGRATION_PLAN.md)§5.2是唯一44项主账。
A–H含调查、资源、事务、显示和发行，不是操作次数。
源键库存、观察索引与批准实屏项分开。
词表存在不新增实屏门；一张父图可供多项引用。
代表项不抵全键覆盖；每项仍须独立判定。
整轮表和记录流程沿用[统一入口](../../../../tools/acceptance/README.md)。
已有表继续填写，不因中断或单项补验重新prepare。
本技能不关闭Windows、安装包或发行项。

## 合批依据

本轮只设一个当前完整候选入口，所有当前runner共用。
入口绑定制品路径、摘要与冻结源码，不硬编码旧版。
沿已验完整底座补增量；失败候选不替换成功底座。
证据按候选与影响范围复用，不因runner改路径全量重测。
字体实现或库改变时，按[重测规则](evidence.md#复用与重测)回归。
原厂对照标明未注入，不抵候选显示。

按`语言组合 + 候选/资源 + 场景 + 启动方式/初始状态`合并。
分别记录Cavalry与Switcher界面语言。
正常首帧采完，沿同PID继续兼容显示；helper不抵正常启动。
普通显示不额外要求登录；不同候选或场景不混证据。
每批只列条件、细项ID、驱动/输入、动作和回交。
先查[成功驱动](../../../../tools/acceptance/DRIVERS.md)和私人完整依赖。
保留原动作及必要动画节拍，只改本轮输入绑定。
启动环境记录实际Popen参数；计划不冒称载库。
host有时限时，先完成编译与驱动准备，再启动。

资源和ABI合同先离线准备，不授实屏PASS。
正常Apply可接本语显示；Switcher四语不缩成宿主三语。
故障、恢复与实验偏好另批，先保存前像。
首帧和正常性能使用正常启动；helper不抵该证据。

## 一个语言批次的顺序

1. 本批若测正常首帧，先采首次可见文字，不先开菜单或刷新。
2. 证明场景实际加载。复用同版本输入证明时，仍核当前名称与行数。
3. 核静态标签、空提示、名称和tab，再切枚举并恢复默认值。
4. 连续读属性提示、节点说明和脚本帮助，各核实际popup。
5. 做搜索并清空；先保存查询读回，再恢复视图、FPS等状态。
6. 本语首帧及兼容显示都完成后，再切下一语；编辑链路用独立副本。

同语兼容显示连续完成，不按插件反复切语。
场景可在同语内切换；不先轮三语首帧再轮稳定显示。
重开、Restore或故障注入前，封存前序结果。
Restore走产品事务，不用实验回滚冒充。

## 中断后续验

host超时或检查器失败，只续剩余或受影响阶段。
新PID重绑候选、语言和实际载库，不使旧结果自动失效。
同语helper计划经现有平台生命周期入口运行。
它先快照偏好与独立workspace，再执行动作和回交。
正常切语仍走产品事务，不复制owner或marker。
下一兼容步骤未就绪时，采完立即停播并关闭exact PID。
写者退场后回交配置，再离线审图和写文档。
SIGTERM仅记清理，不计正常Quit通过。
