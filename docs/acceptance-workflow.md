# Cavalry 2.8 整轮验收 SOP

## 一份整表贯穿一轮

统一入口为 `tools/acceptance/README.md`。
整轮副本默认放 `tools/acceptance/runs/<本轮编号>/`。
该目录由Git忽略。私人方案与驱动索引放同级`local/`。
启动完整流程时生成一次整表，不为单项另建表。
原始截图、日志和录像保存在本轮目录内。
不得把填写副本、截图或私人方案加入提交。
完整命令见统一入口的开始、记账、检查和收口四步。
公开仓库只保留工具与规则，不提交实跑证据。

逐项检查，不以场景整体通过代替细项判定。
同语、同场景的多个细项共用启动、动作和证据。
每个细项仍保留独立结果与证据引用。
需改变启动条件的实验独立执行，不冒充正常首帧。
同语helper计划通过平台生命周期入口运行，不直接跑通用编排器。
批末先证明本轮PID全部退出，再精确回交偏好及独立工作区。
正常切语通过产品事务回交，不复制owner或配置原字节。

## 检查与修复闭环

1. 按本轮候选、资源与平台确认目标适用性。
2. 复用成功脚本；核对其候选、路径和前置状态。
3. 检查每个细项，记录实际结果与证据。
4. 失败时填写 `FAIL`，不打勾。
5. 在 `attempts.jsonl` 追加失败记录。
6. 找根因、修复，并记录新候选与影响范围。
7. 复验失败项及受影响项；未受影响的有效证据复用。
8. 复验通过后追加记录，再将该行改为 `PASS` 并勾选。
9. 执行表单检查；剩余 `FAIL` 或 `PENDING` 不得收口。

优先用`record`命令同步整表和历史。手工记录也须保留失败。
失败项不得改成`REUSE`或`N/A`绕过修复复验。

失败记录示例，每个 JSON 对象占一行：

```json
{"id":"表单中的ID","at":"ISO时间","candidate":"失败候选","result":"FAIL","evidence":"evidence/failure.png"}
{"id":"表单中的ID","at":"ISO时间","candidate":"修复候选","result":"PASS","evidence":"evidence/pass.png","fix":"根因与修复提交","impact":"受影响项及复验结果"}
```

保留前次失败，不用最终截图覆盖失败截图。
不得为了通过而删目标、缩减预期或扩大白名单。
`REUSE` 必须写明旧证据与当前候选的适用关系。
`N/A` 必须有范围依据和说明；它不是通过。
已确认的非阻断事项保留依据，不擅自新增豁免。
检查器验证记录结构；验收人负责证据真实性。

## 阶段交接

macOS 完成本平台适用项及共用项，冻结证据。
Windows 另建该平台整轮副本，复用流程与可移植驱动。
平台差异使用平台适配器，不能继承 macOS 实机 PASS。
Windows接手包见`tools/acceptance/local/handoff_windows/README.md`。
Windows剩余任务顺序与case批次见`tools/acceptance/local/handoff_windows/HANDOFF-TASKS.md`。
打包器只含公开工具、可核验源码差异与本地离线夹具。
打包器不读取Mac整表、截图、App或私人驱动。
Windows先核对基线提交、补丁和源码SHA，再创建一次整轮表。
共享编排器不代表Windows GUI驱动已接线。
无驱动的项目由Windows实现适配器，或人工逐项执行。
发布阶段单独确认编译、安装包、更新与发布授权。
表单检查通过不触发上传、打标签或发布。
交接时人工核对Mac源码提交与Windows构建源码一致。
分别记录两平台制品摘要；不同平台不要求制品摘要相同。
修复跨平台代码时列明影响范围，不继承受影响的旧证据。

## Python编排与等待

两平台共享Python编排、步骤顺序与证据格式。
平台动作使用各自实现；Windows不回退调用AppleScript。
每步声明表单ID、读取目标、动作、就绪条件和采集命令。
用`{run}`引用本轮目录，`{evidence}`引用当前步骤目录。
跨步骤回执不得写死首次输出路径，续跑时使用新轮目录。
就绪探针返回0表示就绪，1表示未就绪，其余值表示失败。
探针就绪后立即采集；没有就绪探针的同步动作完成后直接采集。
不在正常步骤插入固定长等待；仅未就绪时短轮询。
必要的性能观察窗口保留在该采样动作内，不当空等删除。
同面板一次读取多个目标；OCR与全文审查放到采集之后。
events.jsonl记录动作、探针和采集耗时及原始读回。
原始读回在本步采集后批量落盘；归档耗时单独计数。
失败停止当前批次，保留前序证据；修复后仅续跑受影响步骤。
每批完成或失败后立即停播并关闭自有测试进程。
只有下一兼容步骤已就绪时保留PID；分析前不闲置播放。
动作计划可声明cleanup；失败、超时或人工中断后也执行收尾。
清理只定位本批回执的exact PID，不批量结束同名应用。
强制清理不计正常Quit通过；回交仍核配置与布局。
CAPTURED_PENDING_REVIEW只表示采集完成，表单仍须逐项审查。
只读状态的步骤记READBACK_PENDING_REVIEW，不冒充截图完成。

## 当前工具边界

目录含44主项映射，并从批准源展开多语言目标。
schema2区分完整源键库存与批准的实屏检查项。
插件库存保留全部324源键，不带验收结果。
其中69源键按既有裁决进入三语实屏检查。
源键存在不等于新增逐键实屏要求。
Group、Null、帮助与其他场景范围不变。
ToolHelp保留66源键的198条三语库存记录。
实屏沿既有四工具组，不逐源键增加测试。
库存引用工具组不继承该组的显示结果。
已有schema1副本须显式执行`migrate`，不得另建表丢弃历史。
已迁移的旧schema2使用`amend-toolhelp`修订范围。
该命令独立归档父表，不覆盖既有迁移归档。
迁移归档原表、session及全部attempts，再写逐项crosswalk。
库存映射不计PASS或N/A；未解决FAIL不得转库存。
检查器同时核对原件、迁移结果和crosswalk。
目录数量不是新增人工测试次数。
同一次动作能覆盖的细项使用同一证据。
未逐一核对的历史细项不得宣称已完整覆盖。
工具自测通过不等于历史GUI脚本已经全部串接。

## 场景与观察的边界

同语同场景的观察共用一次动作和截图。
Timeline六名五态双表面的180个索引不等于180次操作。
每语五个父场景各核一张整窗图。
逐名身份、全文与Measure/Draw保留原锚点。
屏外不授字形信用，裁切不得越界。

原Null验收只含Shape页签与继承Opacity。
完整源表不自动新增属性、提示和枚举实屏门。
当前macOS表为2630个case，另保留完整库存。
旧表用amend-scenes显式修订，保留三原件及全部历史。

100个官方示例菜单核菜单标题和状态覆盖。
Clouds与Bridge核已批准的两例真实打开。
两者分别记账，不扩为100次工程实跑。

## 动作提交、界面就绪与实际消费

菜单命令返回不表示目标状态已经出现。
沿用已验动作和必要的菜单动画节拍。
随后按预期行数、选择或窗口状态有界轮询。
状态出现后立即读回和采图，不再固定长等。
不得因第一次读回仍是旧状态而重发创建动作。

面板切换会隐藏兄弟视图。
先用正常入口恢复目标面板，再读取其可见控件。
视图隐藏不等于数据缺失。
模型身份保持英文时，不要求模型角色返回本地化名称。
名称显示由原图判定；实际节点类型由只读API判定。

翻译包副本可位于不同路径。
内容复用核源SHA与来源，不强制副本路径相同。
App、进程与写入目标仍须绑定本轮真实路径。
私有测试控件的固定名称必须来自当前语种包。
缺少某语种的测试白名单不是产品漏译。
